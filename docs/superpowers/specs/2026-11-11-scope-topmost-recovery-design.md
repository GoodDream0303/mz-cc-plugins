# Scope 置顶自动恢复

用户已选择：复用现有每秒刷新循环，检查实际窗口层级，仅在置顶异常时恢复。

## 目标和约束

- 开启置顶时，恢复置顶标志丢失，以及标志仍在但被普通窗口遮挡的情况。
- 未被遮挡时不重排窗口；其他置顶窗口不触发恢复。
- 取消置顶后不检查、不恢复；隐藏或最小化时不显示或还原窗口。
- 恢复使用 HWND_TOPMOST / SWP_NOACTIVATE / SWP_NOMOVE / SWP_NOSIZE，不抢焦点、不改变位置大小。
- 不新增线程、进程、依赖或定时器，不扫描或打开其他进程，不修改用户配置。
- 只修改开发 worktree，日常修改不自动发布或修改正式缓存。

## 方案比较

1. **已选：每秒检查并按需恢复。** 复用 poll；实现小，正常情况下约一秒内恢复。读取窗口属性并提前结束枚举，实际成本须测量。
2. 窗口切换事件监听。响应更快，但增加回调生命周期和事件去重，不采用。

## 实现边界

Windows 原语放在现有 src/win32_support.py，Scope.poll 仅在 pinned 时调用。
从 Tk 窗口取得真实顶层包装窗口；若已置顶，检查其上方可见、未最小化的普通窗口是否与其矩形相交。
EnumWindows 回调在到达自身或发现遮挡时结束，不读取窗口标题、会话数据或进程信息。
API 失败按现有 poll 错误日志约定报告，后续刷新仍可重试；不宣称定位了系统异常的触发根因。

## 验收

真实 Windows/Tk 自建窗口覆盖丢标志、正常与其他置顶窗口、不置顶、隐藏/最小化及无重叠/零面积矩形。
标志/层级不一致使用真实窗口顺序，仅模拟本窗口的置顶标志读取；不声称稳定复现了系统内部异常。
恢复前后比较前台窗口与窗口矩形；运行现有产品和根目录回归，测量稳定状态检查耗时。
连续人工切换与休眠恢复的长期体验不由短时自动测试代替。
