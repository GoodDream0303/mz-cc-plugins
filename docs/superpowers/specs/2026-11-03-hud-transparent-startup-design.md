# HUD 启动与升级兼容设计

状态：0.5.1 实现与自动验证完成；真实交互验收范围见 codex-hud/docs/validation.md。

## 目标与约束

- 目标 Windows x64 环境已有官方 Codex 和 Node.js 20+；不增加安装 Node 的流程。
- 日常命令保持 `codex`、`codex resume <ID>`，参数、当前目录、输入输出和退出码保持官方语义。
- 市场安装后由插件引导一次入口初始化；此后插件升级不要求用户反复运行 setup。
- HUD 在官方 Codex 启动前发生故障时，提示并直接运行官方 Codex；官方进程启动后不得因错误或非零退出码再次启动会话。
- 默认六行、现有语言和显式显示偏好保持不变。
- 不修改官方程序、审批、安全、daemon、Hook 信任记录、全局 PATH 或 Windows Terminal 设置；不自动发布。

## 方案取舍

采用固定位置的 PowerShell 入口，运行时解析有效插件和官方命令。保留普通 `codex` 习惯，同时将插件缓存清理与已加载函数解耦。

继续把版本路径写入 Profile 不能解决已打开窗口的问题；另设 `codex-hud` 启动命令不符合用户要求，均不采用。

## 入口与有效版本

- 初始化将必要的 PowerShell 引导脚本部署到 HUD 自己的固定运行目录；Profile 的受管块仅引用该入口和用户选择的配置路径，不引用版本化插件缓存。
- 已加载函数每次调用均重新解析插件及官方命令，不将安装路径永久捕获在闭包中。
- 插件身份限定为初始化所选市场及插件；以官方安装状态确定版本和是否启用，校验对应包身份和必要文件。不得以目录修改时间、残留目录或其它市场的同名插件替代。
- 查询不可用、超时、插件已禁用/卸载、缓存缺失或包损坏时，跳过 HUD，调用当前可定位的官方命令。
- 解析官方命令时排除 HUD 函数，避免递归；支持既有 npm 启动入口和原生可执行程序。官方安装路径变化后重新定位。
- 引导脚本本身缺失时，受管 Profile 块仅作提示，不能遮蔽原有官方命令。

## 故障回退边界

- 入口检查、配置读取、后端校验及已确定尚未执行官方程序的启动失败可以回退。
- Node 不可用属于运行时故障，由 PowerShell 层回退；不把安装 Node 变成正常流程。
- 正式 Codex 的非零退出码直接传回；不把登录、参数、模型、网络等官方错误当成重启理由。
- 后端可能已经执行启动命令时，只有能证明未启动官方程序才能回退；结果不明确时报告诊断，禁止重复启动。
- HUD 面板创建或遥测绑定失败时，已经运行的 Codex 继续工作。
- 回退提示简短且不打印调用参数、凭据或完整环境。

## 首次安装与迁移

- 首次使用由 hud-start 引导预览并应用一次初始化，沿用现有受管块校验、备份和用户 Profile 内容保护。
- PS5/PS7 分别处理实际使用的 Profile；迁移旧受管块后，新开窗口或重新加载一次 Profile。无法远程更新其它已打开 PowerShell 的内存函数。
- 不声称市场安装本身能将当前普通 Codex 会话迁入 HUD 宿主；初始化对后续正常启动生效，必要时通过原来的 resume 命令恢复。
- 沿用随包分发的后端及运行代码，无需编译。按官方提示审核当前 Hook；不能将安装状态或 doctor 就绪视为 Hook 已获信任。
- 用户自定义后端路径保留；由旧包自动选择的随包后端路径随有效插件切换，避免升级清理缓存后失效。
- 更新 hud-start/hud-doctor 和 README，让新环境只有一次清晰的初始化流程。

## 验收

1. PS5/PS7 的同一个已加载入口，在插件从 A 升为 B 且 A 被删除后，下一次 `codex` 使用 B，无需重载 Profile。
2. 缓存损坏、插件禁用/卸载、Node 缺失、配置损坏、后端校验失败时，官方程序启动一次并收到原参数，退出码一致。
3. 官方程序已经启动后返回非零、以及后端启动结果不明确时，都不能再启动第二个会话。
4. 官方 npm/native 入口原地更新及安装路径变化后重新解析；维护命令与非交互输入继续按原语义执行。
5. 无开发依赖的复制包在隔离配置和 PS5/PS7 Profile 中完成首次初始化；模拟官方入口及后端故障验证行为，不隐式启动真实模型会话。
6. 自动检查通过后明确列出实际市场全新 Windows 安装、Hook 审核和真实终端交互仍需人工验收的项目，不将隔离测试冒称完整实机验收。
